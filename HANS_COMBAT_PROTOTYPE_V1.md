# Ганс — боевые анимации, прототип v1

Основа: актуальная `main`, `66cb79f` (после PR #36).
Ветка: `codex/hans-combat-prototype-v1`.
Проверено в **Godot 4.6.3 stable**, Linux. Указанный в README Godot 4.6.2 отдельно не запускался.

## Результат и границы подключения

Добавлены две анимации, переиспользуемая визуальная сцена, просмотрщик и **отдельный вариант существующей тестовой арены**. Все ранее существовавшие файлы проекта сохранены побайтно: квесты, девять NPC, Ганс на карте, обычная арена, сюжетный бой, диалоги, сохранения, настройки проекта и оригинальная графика не менялись.

Прототип намеренно не включён по умолчанию в обычной арене или первой главе. Это предварительный художественный материал, который пока нельзя считать утверждённой заменой. Тестовый вариант арены наследует действующие `combat_arena.gd`, шесть сценариев, UI и движок расчётов; при **уже рассчитанном промахе по Гансу** показывает Dodge. Нового броска уклонения, действия игрока, неуязвимости, изменения урона или стоимости хода нет. Попадание продолжает наносить урон, даже если визуальный Dodge запущен отдельно.

## Как открыть

1. Открыть существующий `HutorReborn/project.godot`.
2. Открыть `scenes/combat/prototype/HansCombatPreview.tscn`, нажать **F6**.
3. Использовать **Combat Idle / Dodge**, ползунок скорости, поля длительности кадра, выбор тёмного/светлого фона и паузу.
4. Нажать «В тестовую арену с прототипом», выбрать один из шести существующих сценариев. Кнопка «В меню» в этом варианте возвращает в просмотрщик.
5. «В главное меню» просмотрщика возвращает в обычное меню игры. F5 проекта по-прежнему запускает обычную игру с прежней графикой.

Запуск из командной строки:

```sh
godot --path HutorReborn res://scenes/combat/prototype/HansCombatPreview.tscn
```

На Windows можно использовать путь к своему Godot 4.6.x вместо `godot`.

## Ресурсы и точные параметры

Распакованы все **30 файлов** пакета в `assets/characters/hans_combat_prototype_v1/`: 24 отдельных PNG, два горизонтальных strip, два GIF-превью, исходные README и manifest. Их SHA256 совпадают с ZIP; источники не перерисованы и не очищены. Дополнительно созданы `frames.tres`, `alignment.json`, `source_checksums.json` и настройки импорта PNG.

| Параметр | Combat Idle | Dodge |
|---|---|---|
| PNG в исходнике | 12 × 444×444 RGBA | 12 × 357×358 RGBA |
| Уникальные изображения | **7** | 12 |
| Последовательность | `1..12, 11..2` | `1..12, 11..2` |
| Шагов воспроизведения | 22 | 22 |
| Длительность шага при ×1 | 115 мс | 52 мс |
| Скорость SpriteFrames | 8.695652 кадра/с | 19.230769 кадра/с |
| Полный проход | 2.530 с | 1.144 с |
| Повтор | Непрерывно | Один проход → Idle с кадра 1 |

Индексы крайних кадров не удвоены. При этом **в самом исходном Idle уже есть дубли**: 02=12, 03=11, 04=10, 05=09, 06=08. Получается обратимое движение из семи уникальных поз, развёрнутое по предписанному manifest; мы не выдаём его за 12 уникальных фаз. Порядок не заменён самовольно на другой.

Используются отдельные PNG через `AtlasTexture` с прозрачным полем, а не ошибочная двумерная сетка strip. Горизонтальные strip сохранены как исходные материалы, но не воспроизводятся вторым способом.

Импорт: lossless, без mipmaps, без premultiplied alpha и **без автоматического исправления границ alpha**. Оба `AnimatedSprite2D` используют Nearest. Проверка сравнивает все RGBA-байты импортированных 24 кадров с исходными PNG.

### Опора, масштаб и переход

`HansCombatVisual.tscn` содержит два `AnimatedSprite2D` с общим SpriteFrames. Показывается только один. Масштабы постоянные: Idle ×1, Dodge ×1.24 — компенсация разного исходного увеличения. Пропорции X/Y всегда одинаковы; покадрового изменения масштаба, растягивания тела и маскирующего crossfade нет.

- Кадры помещены в прозрачный canvas 512×512 через margin, без удаления исходных пикселей. Опора находится в `(256,480)`; sprite offset — `(-256,-480)`.
- За опору принят устойчивый нижний участок правой подошвы. Подготовительные измерения анализировали нижнюю полосу с alpha >180, игнорируя верхнюю постороннюю линию и единичный пограничный шум. Сдвиги между исходниками записаны в `alignment.json` и применены в AtlasTexture. Это только перенос изображения, не деформация анатомии.
- У Idle сдвиг опоры между файлами составляет около одного исходного пикселя; у Dodge корректируется небольшой общий дрейф. Существующее изменение постановки **левой** ноги и формы обуви не устранить одной общей опорой — это дефект/движение исходной графики, требующее художественного решения.
- В просмотрщике общий равномерный масштаб 0.7. В тестовой арене — 0.184: стоящий персонаж имеет высоту около 79 px, сопоставимую с прежним Гансом в карточке боя. Это не изменяет масштаб игрового Ганса на карте.
- Idle цикличен; Dodge не зациклен и возвращает Idle по `animation_finished`. Повторный Dodge во время выполнения отвергается, кнопка временно отключена. Idle позволяет явно прервать Dodge. Пауза удерживает текущую фазу.
- Переход не даёт дополнительного смещения корневого узла и не показывает оба силуэта одновременно. Небольшая смена деталей на стыке остаётся из-за разных исходных поз; это не заявляется как окончательно вычищенный художественный переход.

В Inspector компонента доступны `idle_frame_ms`, `dodge_frame_ms`, `playback_speed`. Настройки просмотрщика действуют только в текущем экземпляре, общий ресурс и обычная игра не переписываются. Пределы ползунка просмотрщика ×0.1–2; компонент также поддерживает ×3 для существующего ускоренного режима арены. Для правки опоры можно редактировать margin соответствующих AtlasTexture в `frames.tres`; JSON фиксирует использованные измерения и сам по себе не является runtime-настройкой.

## Обнаруженные графические дефекты — остаются открытыми

Это **реальные дефекты предоставленных изображений**, а не ошибки импорта. Они намеренно видны на светлом фоне и в записи.

| Дефект | Наблюдение и причина | Что нужно дальше |
|---|---|---|
| Потеря непрозрачности внутри персонажа — существенный | Светлый фон просвечивает через лицо/бороду, плащ, ремни, руки и брюки. Пороговое удаление чёрного уничтожило тёмные части самого персонажа; исходный README предупреждает об этом. | Восстановить внутреннюю маску непрозрачности и тёмные материалы вручную, желательно из версии **до** удаления фона. Заполнить всё тёмным автоматически без различения контура нельзя. |
| Чёрные/тёмные каймы и зернистая alpha | Полупрозрачные пиксели контура сохраняют тёмный фон. В Idle около 16–18 тысяч частично прозрачных пикселей на кадр, в Dodge около 10–12 тысяч. Не каждый такой пиксель является ошибкой; дефект виден именно по нежелательному просвечиванию и кайме. | Ручная очистка контура с проверкой на обоих фонах, без общего blur. |
| Посторонняя линия над Dodge и шум у границ | В первых кадрах Dodge на светлом фоне появляется тонкая горизонтальная линия. Ненулевые пиксели ряда кадров также доходят до исходных границ изображения. Canvas её не создаёт и не прячет. | Удалить посторонний шум в исходных кадрах; проверить полноту плаща/обуви. Само касание границы не объявляем доказанным обрезанием анатомии. |
| Рябь фактуры и меняющиеся мелкие детали | При движении меняются рисунок ткани, блики, пальцы/рукоять, форма плаща и обуви. Видно во времени, а не только на одном кадре. | Покадровое согласование силуэта и деталей. Регистрация стоп не восстанавливает отсутствующую анатомию. |
| Левая стопа и стык двух клипов | При уклоне левая нога меняет постановку; фактура/поза на границе Dodge→Idle не полностью совпадают, несмотря на согласованную опору и увеличение. | Художественно уточнить работу ног и согласовать начальную/возвратную позу. Не скрывать это растягиванием или двойным силуэтом crossfade. |
| Ограниченное разнообразие Idle | 12 исходных PNG — только 7 уникальных изображений, уже с обратной частью движения. | Утвердить, нужен ли именно текущий manifest или новый ряд уникальных фаз. В этом PR выполнен данный manifest без самовольной замены. |

В ZIP нет полноценного исходника до автоматического удаления фона: названия прежних GIF/APNG в поле `source` manifest — сведения о происхождении, а не файлы для восстановления. Изображения для окончательной дорисовки понадобятся отдельно. **Художественного утверждения этот PR не подразумевает.**

Тест чтения исходного PNG через `Image.load_from_file` предупреждает, что так нельзя загружать ресурсы в экспортированной игре; это **только анализатор теста**, runtime использует импортированные Texture2D через SpriteFrames. Полный повторный ручной прогон главы не выполнялся: все её прежние файлы неизменны, проведены перечисленные регрессии.

Повтор теста:

```sh
godot --headless --path HutorReborn --script res://tests/verify_hans_combat_prototype.gd
python3 -B HutorReborn/tests/verify_hans_combat_sources.py --archive /path/Hans_Combat_Prototype_v1.zip
```

Вторую команду можно запускать без `--archive`: тогда проверяется сохранённый список исходных SHA256. Для неё нужен Pillow.

## Что проверить вручную на Windows

1. F6 просмотрщика: несколько циклов Idle на обоих фонах; сравнить отсутствие лишней паузы на концах последовательности.
2. Dodge на ×1, ×0.5 и ×2; повторное быстрое нажатие, Idle во время Dodge, пауза/продолжение. Проверить возвращение к Idle без одновременного второго силуэта.
3. Сверить опору правой стопы с линией, отдельно оценить перемещение левой стопы, работу коленей, плаща и кистей. Убедиться, что полный исходный кадр виден, включая проблемные пограничные пиксели.
4. Проверить Inspector-длительности 115/52 мс и изоляцию настроек двух экземпляров сцены. Утвердить тайминги после покадрового художественного исправления.
5. Открыть тестовую арену из просмотрщика: проверить попадание/промах по Гансу, ускорение ×3, restart во время показа, другие сценарии и возврат в просмотрщик.
6. F5 проекта: обычная арена и сюжетный бой должны показывать прежнего Ганса; проверить обычную загрузку сохранения и переходы между домами.
