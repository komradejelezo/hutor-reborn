Все четыре конфликта затрагивали добавления соседних регистраций, а не несовместимые игровые алгоритмы. Сохранены изменения обеих сторон:

## Изменения только в тестах

Ожидания `verify_residents_545.gd` и `verify_residents_546.gd` согласованы с одновременным присутствием моделей сына и трактирщика. Добавлены проверки фактического пути SpriteFrames для каждого ID и размера портрета каждого из четырёх персонажей. Оба файла имеют одинаковый контракт, поэтому запущен общий вариант `546`.

Старый `verify_daily_lifecycle.gd` первоначально дал два сбоя проверки смещения при повторном входе. Изолированный запуск **того же теста** воспроизвёл один из них на исходном `main` и оба на исходном PR #28. ID и шаг занятия сохранялись; NPC законно продолжали двигаться во время затемнения. Фиксированный предел 25 пикселей не учитывал прошедшее физическое время и привязку к навигационной сетке.

Исправлен **только тест**, без изменения NPC: предел учитывает скорость × прошедшее число физических кадров и одну диагональ клетки сетки; для ожидающего NPC без истёкшего ожидания учитывается только сетка. Проверки того же ID и того же шага оставлены. [Сравнение исходных версий](deliverables/Stage546/main-sync/baseline-comparison.json). Финальный тест проходит 163 проверки.

**Конфликты устранены в существующей ветке PR #28. Автоматическое объединение не выполнялось.**
