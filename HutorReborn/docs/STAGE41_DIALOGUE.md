# Этап 4.1 — универсальные диалоги

Основа: `main`, коммит `3157b93139bdd9803582c247a919045f784b8fa4` с объединёнными этапами 3.1–3.3. Создана отдельная ветка `codex/stage41-dialogue-system`; карта и ресурсы этих этапов не редактировались.

## Запуск

1. Открыть `HutorReborn/project.godot` в Godot 4.6 и дождаться импорта.
2. Обычный **F5** запускает прежнюю «Кривую Сосну», без новых NPC, кнопок или автоматического разговора.
3. Для проверки открыть `scenes/demo/dialogue_demo.tscn` и нажать **F6**. Эта отдельная сцена загружает сохранённую деревню и добавляет только кнопку «Поговорить со старостой». Нажать её мышью или Enter.
4. Проверить три ответа, линейное продолжение и окончание разговора. Кнопка позволяет повторить демонстрацию после завершения или отмены.

Из командной строки:

```sh
godot --editor --path HutorReborn
godot --path HutorReborn res://scenes/demo/dialogue_demo.tscn
```

| Ввод во время разговора | Действие |
|---|---|
| E / Enter / Num Enter при печати | Показать текущую реплику целиком |
| E / Enter без вариантов ответа | Следующая реплика или завершение |
| ↑ / ↓ | Выбрать ответ, с циклическим переходом и прокруткой |
| Enter / Num Enter | Подтвердить выбранный ответ |
| Левая кнопка мыши | Выбрать ответ |
| Колесо над текстом / ответами | Прокрутить соответствующую область |
| Esc | Отменить разговор, без открытия паузы |

E не подтверждает ответ: это защищает от случайного выбора при раскрытии текста. Удержание открывающей клавиши и её автоповтор не пропускают начало. Во время появления/закрытия окна игровой ввод остаётся заблокирован.

## Архитектура

Система состоит из отдельных частей:

- `dialogues/*.json` — UTF-8 графы реплик и переходов.
- `HutorDialogueData` (`scripts/dialogue/dialogue_data.gd`) — загрузка, глубокое копирование и проверка графа. Проверяет типы, повторяющиеся ID, начальную реплику, все ссылки и неоднозначные окончания. Ошибка возвращается в `errors`, без открытия окна и блокировки управления.
- `DialogueManager` (`scripts/dialogue/dialogue_controller.gd`) — один autoload, одна модальная сессия. Обходит граф, маршрутизирует ввод, блокирует/восстанавливает существующие состояния игрока, камеры и датчика взаимодействий. Когда разговоров нет, обработка ввода отключена. Окно загружается только при первом разговоре, поэтому первая загрузка проекта не требует уже импортированных UI-текстур.
- `scenes/ui/dialogue_window.tscn` и `dialogue_window.gd` — оформление, печать, портрет, кнопки и прокрутка. Окно ничего не знает о Гансе, карте и квестах; данные реплик передаются контроллером.
- `HutorDialogueInteractable` — переиспользуемый компонент существующей системы осмотра. Возвращает путь к диалогу; небольшой дополнительный переход в `world.gd` передаёт его контроллеру. Обычные описания и пауза остаются прежними.
- `scenes/demo/dialogue_demo.tscn` и `dialogue_demo.gd` — отдельная, добровольно запускаемая демонстрация. NPC и физические тела не создаются.

Во время разговора используется прежний `controls_locked`, без изменений в движении Ганса. Датчик взаимодействий приостановлен; Camera2D временно получает `PROCESS_MODE_DISABLED`, что останавливает даже незавершённое сглаживание. Позиция, zoom, пределы и параметры камеры не меняются. Все предыдущие состояния, включая уже существующую внешнюю блокировку, восстанавливаются после исчезновения окна. Мир не ставится на паузу: лес, огни и дым остаются видимыми и продолжают жить.

При удалении игрока/сцены окно закрывается и освобождает сессию. Нельзя одновременно открыть разговор и прежний осмотр/паузу. Неактуальная удалённая точка взаимодействия проверяется перед восстановлением подсказки.

## Данные реплик

```json
{
  "id": "traveller_meeting",
  "start": "hello",
  "nodes": [
    {
      "id": "hello",
      "speaker": "Путница",
      "portrait": "res://assets/portraits/traveller/neutral.png",
      "emotion": "thoughtful",
      "portraits": {
        "neutral": "res://assets/portraits/traveller/neutral.png",
        "thoughtful": "res://assets/portraits/traveller/thoughtful.png"
      },
      "text": "Куда ведёт эта дорога?",
      "choices": [
        {"id": "village", "text": "К хутору.", "next": "thanks"},
        {"id": "leave", "text": "Мне пора.", "end": true}
      ]
    },
    {
      "id": "thanks",
      "speaker": "Путница",
      "text": "Благодарю. Доброй дороги.",
      "end": true
    }
  ]
}
```

Пути выше — инструкция для будущих ресурсов, эти портреты не создавались.

| Поле | Назначение |
|---|---|
| Корневые `id`, `start`, `nodes` | ID разговора, ID начальной реплики, массив реплик |
| `id`, `speaker`, `text` реплики | Обязательные непустые строки; ID уникален в пределах разговора |
| `portrait` | Необязательный путь к PNG по умолчанию |
| `emotion` | Ключ эмоции, по умолчанию `neutral` |
| `portraits` | Необязательное соответствие эмоций путям PNG |
| `next` | ID следующей линейной реплики |
| `choices` | Массив ответов с уникальными `id`, текстом `text` и переходом `next` либо `end: true` |
| `end: true` | Завершить после прочтения реплики; у такой реплики нет `next`/`choices` |

Каждая реплика имеет ровно один вид продолжения: `next`, непустые `choices` или `end: true`. Каждый ответ имеет либо непустой `next`, либо `end: true`. Ссылки должны вести на существующий ID. Циклические разговоры допускаются: переход выполняется только по вводу игрока, автоматического бесконечного обхода нет. Одинаковый файл может использоваться любыми будущими персонажами; разные говорящие могут сменяться в одном графе. Активный граф не следует менять из стороннего кода.

Для добавления реплик скопировать JSON, задать корневой ID, создать уникальные узлы и соединить их `next`/`choices`. Полный пример с тремя ветвями и общим завершением — `dialogues/elder_demo.json`. Это проверочный текст, сюжетные задания он не выдаёт.

При будущем экспорте сборки включить `dialogues/*.json` в фильтр дополнительных файлов: они читаются через FileAccess, а не импортируются как сцены.

## Добавление персонажа и портретов

1. Создать отдельный JSON с его именем и репликами. Подготовить PNG с прозрачностью, например в `assets/portraits/<character>/`; никакая фиксированная величина или соотношение сторон не требуется.
2. В нужных репликах указать `portrait` и при необходимости `emotion`/`portraits`. Сначала выбирается PNG нужной эмоции, затем общий `portrait`, затем `portraits.neutral`; при отсутствии подходящего ресурса показывается декоративная рамка с орнаментом. Портрет сохраняет пропорции (`KEEP_ASPECT_CENTERED`) и Nearest.
3. В будущую сцену персонажа добавить `Marker2D` со скриптом `dialogue_interactable.gd`. Указать `title`, `dialogue_path`, `reach`; маркер поставить с доступной стороны, вне твёрдой коллизии. Прежний датчик Ганса выберет ближайший доступный маркер с проверкой лучом, а E откроет разговор.

В этом этапе такой персонаж на карту **не добавляется**. Для прямого вызова из теста или будущего компонента:

```gdscript
var manager = get_node("/root/DialogueManager")
if not manager.start_file("res://dialogues/elder_demo.json", player, hud):
    print(manager.last_error)
```

Сигналы для дальнейшего подключения сюжетных систем:

- `dialogue_started(dialogue_id)` — начало сессии.
- `line_started(dialogue_id, line_id)` — показ узла.
- `choice_selected(dialogue_id, line_id, choice_id)` — подтверждённый ответ со стабильным ID.
- `dialogue_finished(dialogue_id, reason)` — `completed`, `cancelled`, `context_exited` либо причина явного `close_dialogue(reason)`.

Квесты, NPC, инвентарь и сохранение сюжетных флагов не реализованы. Обработчик сигнала может безопасно закрыть разговор, не запуская уже неактуальный переход.

## Проверки и результат

Godot **4.6.3.stable.official**, Compatibility / Mesa llvmpipe. Выполнены импорт, графический запуск, отдельный запуск основной сцены и демонстрации из копии без `.godot`.

| Проверки | Успешно |
|---|---:|
| `verify_dialogue.gd` — валидация, все ветки, реальные события клавиш, блокировка/восстановление управления и камеры, защита E, прежний осмотр/пауза, портреты, завершение/удаление контекста | 65 |
| `verify_dialogue_render.gd` — реальные клики мышью, Enter, кириллица, переносы, длинные строки и 12 ответов, прозрачный PNG, прокрутка, окно 2× | 21 |
| `verify_krivaya_sosna.gd` — карта, входы, восемь маршрутов и взаимодействий | 89 |
| `verify_hans.gd` — кадры, анимации и движение Ганса | 82 |
| `verify_stage1.gd` — прежние механики, взаимодействия и пауза | 44 |
| **Всего проверок Godot** | **301** |

`verify_dialogue_invariants.py` дополнительно подтверждает неизменность **572** прежних файлов: вся карта, дома, грунт, растительность, коллизии, освещение, туман, камера, персонаж и исходная графика. Все прежние настройки `project.godot` проверены за вычетом единственной регистрации autoload. Старые SHA-фикстуры этапов 2/3 фиксируют прежние общие файлы `project.godot`/`world.gd`; их не переписывали под новую функциональность. Для текущего этапа используется новый аудит с явным разрешением этих двух изменений и README.

В ходе разработки исправлены обработка неверного типа `end`, восстановление подсказки с удалённой точкой взаимодействия и ранняя загрузка ещё не импортированных UI-ресурсов. Итоговые проверки не выявили ошибок GDScript или загрузки. Единственное предупреждение графического драйвера среды — недоступный V-Sync. Полный вывод: [stage41-verification.log](stage41-verification.log).

```sh
godot --headless --path HutorReborn --script res://tests/verify_dialogue.gd
godot --path HutorReborn --script res://tests/verify_dialogue_render.gd -- /tmp/hutor-dialogue
python3 HutorReborn/tests/verify_dialogue_invariants.py
```

Проверка рендера требует графического сеанса. Она временно показывает имеющиеся технические PNG только для проверки выбора эмоции/прозрачности; эти изображения не подключаются к демонстрационному старосте и не заменяют Ганса.
