# Этап 4.3 — девять жителей «Кривой Сосны»

Добавлена одна популяция из девяти жителей в утверждённую сцену этапа 4.2. Запуск: открыть `project.godot` в Godot 4.6, дождаться импорта, F5. Подойти к жителю и нажать E; ответы выбираются прежними клавишами/мышью. После закрытия разговора возвращаются управление и маршрут.

Основа — `c28abd68f9758fc834a5e95b8f79c7bea224a4b2`, ветка `codex/stage43-residents`. Этап 4.2 представлен отдельным [PR #9](https://github.com/komradejelezo/hutor-reborn/pull/9); этот этап зависит от него. Объединять автоматически не следует. Пока #9 открыт, сравнение PR с `main` включает также изменения 4.2; собственные изменения 4.3 начинаются после указанного коммита.

## Жители и циклы

Вместо окончательных имён используются обозначения по роли. Слова жителей — короткое знакомство, без заданий и утверждения окончательной истории мира.

|---|---:|---|
| `elder` — староста | 30 | Дом, осмотр двора, площадь, возвращение; спокойные продолжительные остановки |
| `innkeeper` — трактирщик | 28 | Вход, бочки/протирка кружки, коновязь, вход |
| `innkeeper_wife` — жена трактирщика | 34 | Вход, подметание двора, припасы, передний двор |
| `woodcutter` — дровосек | 36 | Дом, дорога к лесу, работа топором, привал, возвращение |
| `woodcutter_wife` — жена дровосека | 32 | Дом, работа у поленницы, поворот к сыну, отдых во дворе |
| `woodcutter_son` — сын дровосека | 62 | Игра, короткие пробежки, остановка возле матери; замечает Ганса, зона ограничена двором |

Общий склад и заброшенный дом не заселены. Все точки `HOME` — наружные остановки возле дома, входов в интерьеры нет. `TALK` в распорядке — поворот к родственнику, без дополнительного окна диалога. Разброс времени ожидания ±15% уменьшает синхронность действий. Зоны ребёнка `(1540,740,380,210)` и старика `(410,890,310,170)` ограничивают также поиск пути, а не только его конечные точки.

## Устройство системы

- `scenes/npc/resident.tscn` — единый `CharacterBody2D`, физическая опора по ногам, Nearest `AnimatedSprite2D`, тень, взаимодействие, аниматор и отключённый по умолчанию дым.
- `scripts/npc/npc.gd` — общий автомат `WAIT_PATH / MOVING / WAITING / YIELDING / RECOVERING / TALKING`. `begin_conversation`, `end_conversation`, `set_motion_paused(bool)` приостанавливают движение без сброса текущего шага. `routine_step_changed` предназначен для внешней реакции на остановку.
- `npc_definition.gd` — ID, имя, скорость, тип поведения, SpriteFrames, зона, диалог и список шагов. `routine_step.gd` — действие `HOME/WORK/WALK/REST/TALK/MOVE`, точка, длительность, направление, рабочая анимация и необязательный собеседник. Тип поведения — метаданные для будущих расширений; фактический цикл задаётся шагами и явными свойствами.
- `npc_population.gd` — ссылки на Ганса/атмосферу, регистрация жителей и единый сервис навигации. Жители — обычные редактируемые экземпляры сцен, не генерируются при запуске.
- `navigation_service.gd` — общая `AStarGrid2D` с запретом срезать диагональные углы; сетки переиспользуются для всей карты и двух ограниченных зон. Приоритет дорог задаётся весами 1/3. Статическая сетка 16 px запечена из реальных коллайдеров с запасом радиуса 7 px: 29 760 клеток, 4929 занятых. Физика движения остаётся авторитетной.
- Очередь обрабатывает максимум два запроса пути за физический такт, кеш ограничен 128 путями. Поиск не выполняется каждый кадр. При отсутствии продвижения 1,2 секунды — короткая задержка и новый запрос с временным обходом препятствия; после трёх неудач пропускается текущая цель. Переноса NPC сквозь предметы нет.
- `npc_animator.gd` отвечает только за показ кадров и три частицы трубки; `npc_interaction.gd` адаптирует прежний `HutorDialogueInteractable` и мост мира к `DialogueManager`. Второго окна/контроллера диалога нет. NPC останавливается после принятия сеанса, поворачивается к Гансу, затем восстанавливает прерванное состояние. Удаление говорящего NPC безопасно закрывает сеанс.

Жители имеют слой 4 и маску мира 1, Ганс сохраняет прежние слой 2 / маску 1. NPC соблюдают стены, стволы и ограды, но не являются твёрдым препятствием для Ганса: он может пройти мимо или сквозь дружеского жителя без толкания и перекрытого входа. Движущийся NPC уступает при приближении Ганса; между жителями действует мягкий приоритет. Редкое визуальное пересечение дружественных персонажей допускается — жёсткой толпы/симуляции избегания нет.

Сортировка использует прежний `Actors.y_sort_enabled` и вложенный `Residents.y_sort_enabled`. Спрайт имеет единый холст 96 × 96 с опорой `(48,82)`; взрослые около 44–50 px, ребёнок 33 px из собственного детского исходника. Рисунок Ганса, его масштаб, физика и камера не менялись. Дым старика — 3 CPU-частицы, только на остановке с трубкой; учитывает прежний переключатель F3. Глобальный свет и туман не изменялись.

Во всех строках количество кадров ходьбы указано **вниз / вправо / вверх**. Влево используются те же правые кадры с `flip_h`. Всего подготовлено 99 исходных кадров; девять атласов занимают 4,78 MiB несжатого RGBA. `sprite_manifest.json` содержит SHA-256 исходников, точные прямоугольники нарезки, коэффициенты масштаба, привязки и список недостающего рисунка. Неиспользованные рабочие позы, каталоговые подписи и большие иллюстрации остаются в оригинальной папке; они не выданы за новые анимации.

**Полноценная анимация покоя пока отсутствует у всех девяти жителей.** `idle_down/up/right` — честные статичные первые кадры ходьбы, без зацикливания; `idle_left` — отражение. Необходимо изготовить по три исходных набора idle на каждого из девяти жителей (27, плюс отражение влево). Для старосты дополнительно нужен утверждённый самостоятельный дизайн с четырьмя направлениями ходьбы и покоя; временный этюд не считается окончательным рисунком старосты. Качественную новую графику в этом изменении не подменяли случайными изображениями.

Портреты всех девяти жителей используют существующую заглушку. В каждом диалоге подготовлены отдельные пути `.../<id>/portraits/{neutral,joy,displeased,anxious}.png` — 36 будущих изображений, из которых эмоциональные варианты можно изготовить позднее. Отсутствие файлов штатно обрабатывает система 4.1. Полный финальный набор рисунка этим PR не заявляется.

## Как добавить следующего NPC

1. Создать SpriteFrames с `walk_down/up/right/left`, `idle_down/up/right/left`; для зеркального левого направления разрешены те же текстуры. Оставить опору по ногам `(48,82)` либо согласованно изменить смещение спрайта в отдельной унаследованной сцене. Пропорции и Nearest обязательны.
2. Создать `HutorNpcDefinition` `.tres` в Inspector: уникальный ID, имя, скорость, frames, список `HutorNpcRoutineStep`. Задать внешние проходимые точки, нужную зону и реальные рабочие клипы. Не нужны копии контроллера.
3. Сделать унаследованную сцену от `resident.tscn`, назначить definition; добавить экземпляр в `residents.tscn`. Ребёнку назначается собственный рисунок/радиус, а не уменьшенный взрослый.
4. Создать JSON существующего формата 4.1 в `dialogues/residents/`, указать путь и ID в definition. Пример любого текущего жителя: приветствие с двумя ответами → две реплики → общее завершение. Для портретов можно оставить будущие пути.
5. Проверить точки/цикл физикой, достижимость, входы, разговор и возобновление. После изменения **статических** коллизий карты пересобрать навигацию; сами жители в запекание не входят.

Возможна также воспроизводимая авторская сборка (не нужна для игры):

```sh
python3 tools/prepare_resident_sprites.py --preview /tmp/resident-frames.png
python3 tools/prepare_resident_data.py
godot --headless --editor --path . --import
godot --headless --path . --script res://tools/bake_npc_navigation.gd
godot --headless --path . --script res://tools/build_resident_resources.gd
python3 tools/attach_residents.py
godot --headless --editor --path . --import
```

Python-инструментам графики нужны Pillow, NumPy и SciPy. Обычный Godot-проект не зависит от Python. Сборщики перезаписывают только собственные NPC-ресурсы; не запускайте их поверх ручных изменений NPC без сохранения в Git. Для интеграции будущего игрового времени внешний контроллер сможет выбирать шаги Resource и вызывать приостановку; цикл суток, квесты и расписание по часам в этом этапе не реализованы.

## Затронутые файлы и сохранность основы

Единственное изменение прежней игровой сцены — внешняя ссылка на `residents.tscn` и экземпляр `Actors/Residents` (**четыре добавленные строки**). Существующие дома, дворы, покрытия, коллизии, границы, Ганс, свет и туман не редактировались. README дополнены описанием этапа. `stage43-preserved-files.json` фиксирует SHA 658 прежних файлов и снимок 3039 прежних узлов; проверка удаляет из текста только две новые вставки и требует побайтового совпадения остальной карты с основой. Новые видимые пиксели также проверяются против точной Nearest-выборки исходников.

Журналы финальных прогонов: [Stage43-validation.log](../../deliverables/Stage43-validation.log). Снимки подготовлены отдельным инструментом без сохранения изменений мира: после аудита он только временно останавливает движение и переставляет камеру для обзора. За короткий замер максимум 2 поиска за такт; длинная проверка отдельно подтвердила повторное использование кеша. Полные данные: [Stage43-performance.json](../../deliverables/Stage43-performance.json).

В финальных журналах нет `ERROR` / `SCRIPT ERROR` и проваленных проверок. Графическая среда выдаёт предупреждение о неподдерживаемой смене V-Sync; оно не связано с NPC. На целевой видеокарте остаётся ручной длительный проход по деревне и оценка рисунка/темпа. Недостающие idle, дизайн старосты и портреты перечислены выше; текущие позы не выданы за завершённую анимацию ожидания.
